## 1. 확정된 공통 골격 (9섹션)

```
0. 히어로            — 배지 3 / 제목 / 기관명·지역·핵심메타 / 요약
1. 핵심 조건         — 카드 그리드 (급여·경력·학력·인원·근무 등)
2. ③ 트랙별 핵심 환경 ★ — 트랙마다 내부 완전히 다름 (자유 슬롯)
3. 주요 업무         — 불릿 (연구는 앞에 연구주제 서술)
4. 자격요건·우대사항  — 2컬럼 카드 (우대 빈 배열이면 숨김)
5. 상세 근무조건     — 문단 + 복리후생 태그
6. 위치·근무지       — 주소 + 지도 placeholder
7. 기관 소개         — 소개문 + features + 키워드
8. 리뷰·면접후기·뉴스 — 트랙별 유무 다름
```

**공통 불변 (전 트랙 동일):** 0 히어로, 1 핵심조건, 3 주요업무, 4 자격·우대, 5 상세근무조건, 6 위치.
**트랙별 가변:** 2(③ 핵심환경), 7(기관소개 정보량), 8(리뷰·뉴스 유무).

### 2-1. ③ "트랙별 핵심 환경" — 각 트랙 완전히 다른 성격

| **성격** | 지표+태그 (물리 스펙) | 분류 (직무·사업) | 지표+태그+서술 (복합) | 서술 중심 (연구실 정체성) |

## 3. ★ 확정된 골격 규칙

### 규칙 1: ③ 자유 슬롯
③는 공통 컴포넌트가 아님. 트랙별 전용 컴포넌트를 각각 구현. 골격은 "③ 자리가 온다"까지만 공통, 내부는 트랙 100% 자유.

### 규칙 2: ③↔⑧ 경계 (기관 구조 스펙의 주인)
**원칙: 기관의 구조적 스펙(규모·분류·전문성)은 ③가 주인, ⑧은 소개문(shortIntro/features/키워드)만.**
- 약국: 조제환경 → ③ / 소개 → ⑧
- 산업: 사업분야·대표제품 → ③ / 소개 → ⑧
- 병원: 병상수·진료과·전문약사 → ③ / 소개 → ⑧
- **연구: 예외** — "연구실"이 실질 근무단위라 연구실 정보(PI·주제)가 ③ 주인, 기관 스펙(장비·성과·규모)은 ⑧ 또는 ③ 보조. **트랙 특성이 규칙보다 우선.**

### 규칙 3: 중복 필드 = job 우선, org fallback
전 트랙 공통. 공고폼 값 우선, 비면 기관폼 값. (약국 근무인원, 산업 근무지, 연구 연구분야/주소 등)

### 규칙 4: 값 출처·입력방식 시각 구분
- 정형 선택지값 = 칩(진한). 자유서술 = 문단. 정형 라벨-값 = 라벨(작게)+값(크게).
- 공고 핵심 키워드 ≠ 기관 키워드 (시각 구분).
- id 저장 필드는 label 매핑 상수로 표시(임의 축약 금지).

### 규칙 5: 지원 연락처 로그인 잠금 (전 트랙)
정본엔 원본 저장, 렌더에서 로그인 여부로 분기. 비로그인="로그인 후 지원 연락처 확인". 기관 대표 전화/이메일은 상세 미노출(지원 연락처만).

### 규칙 6: 비공개 필드 (전 트랙)
인증정보(사업자번호·면허·approvedAt 등), 기관 대표 phone/email, OrgManager(내부 담당자)는 상세 미노출.

### 규칙 7: 지도·미연동
지도 실연동 없음 → 모노톤 placeholder. radius 0.

## 4. 디자인 규약 (전 트랙 공통, 프로젝트 확정)
- **radius 0** (rounded-* 금지). pill 예외 = 태그/배지류만.
- **모노톤** 흰/검/회. 브랜드 그라데이션은 **주 CTA(지원하기) 하나에만**. disabled는 회색.
- 옅은 회색 배경 + 흰 카드 + 얇은 border. shadow 최소.
- 표 지양, 카드 그리드 중심. 여백 넉넉("고급스러움=여백").
- 값 크게, 라벨/설명 작고 차분하게. 아이콘 남용 금지.
- 반응형: 데스크톱 다열 → 모바일 1열. 2단 레이아웃(본문+sticky 사이드바) → 모바일 사이드바 제거 + 하단 sticky 지원바.

- **A 지원 카드** (최상단, 주 CTA): 마감상태 / 지원방식 / [지원하기](그라데이션) / 지원연락처(로그인 잠금)

## 6. 데이터 구조 패턴 (전 트랙 공통)
```
XxxJobDetail {
  id / slug / companyId(리뷰 매칭용)
  job: { 공고폼 필드 }   ← 공고별 값
  org: { 기관폼 필드 }   ← 기관 고정값
}
+ 라벨 매핑 상수 (id → label, 폼 config와 1:1)
+ getXxxJobDetail(slug) 헬퍼
+ pharmacyJobDetails 처럼 배열(확장 대비)
```
약국(`pharmacyJobDetails.ts`)이 레퍼런스 구현. 나머지 3트랙도 동일 패턴으로 정본 파일 신설 예정.

## 7. 구현 순서 (확정)

1. **약국 목업을 골격 준수형으로 정리** (현 v2 → 위 규칙 반영, 특히 ③↔⑧ 경계·사이드바)
2. **약국 컴포넌트화** (10-e-2: 사이드바·2단·로그인잠금·모바일 sticky바 포함) — 임시 라우트 `/pharmacy-preview`에서 검증
3. **약국 검증 완료 후** → 기존 `/jobs/[slug]` 약국 분기 연결
4. **타 트랙 순차 구현** (산업·병원·연구, 각각 정본 파일 신설 → ③ 전용 컴포넌트 → 공통 골격 재사용)
5. **최후: Company/CompanyProfile 타입 정리** (4트랙 다 이전 후)

핵심: 공통 골격(0·1·3·4·5·6·7 + 사이드바)은 **공유 컴포넌트**, ③만 트랙별 전용 컴포넌트. → 트랙 추가 시 ③만 새로 만들면 됨.
