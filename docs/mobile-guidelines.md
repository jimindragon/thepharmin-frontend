# 모바일 대응 가이드라인

## 1. 브레이크포인트 표준

이 프로젝트는 desktop-first(max-[Npx]:) 관용구를 사용한다. mobile-first(sm:/md:/lg:)로 새로 작성하지 않는다.

| 값 | 이름 | 의미 |
|---|---|---|
| 640px | mobile layout boundary | 1열화, 카드 전환, 모바일 컴포넌트 전환 |
| 760px | compact layout boundary | 여백 축소, 중간 레이아웃 조정 |
| 1040px | sidebar collapse | 사이드바 → 상단 가로 스크롤 탭 전환 |
| 1120px | global nav collapse | 데스크톱 헤더 nav 전환점 |

- 640/760은 기기 분류가 아니라 레이아웃 경계다. "640 = 폰, 760 = 태블릿"으로 부르지 않는다.
- 새 반응형 작업은 위 4개 값을 우선 사용한다.
- 컴포넌트가 다른 지점에서 실제로 깨지면 국소 브레이크포인트를 허용한다. 단, 표준값 ±40px 이내면 표준값으로 수렴한다.
- 기존 브레이크포인트(767, 1024, 521 등 인접값)는 해당 화면을 수정할 때만 표준값으로 수렴한다. 일괄 치환하지 않는다.
- tailwind.config.ts에 screens를 추가하지 않는다(기존 max-[] 관용구와의 혼선 방지).
- hidden/visible 조건이 브레이크포인트 경계에서 겹치거나 비는 구간이 없는지 반드시 확인한다.

## 2. 내비게이션 구조 (개인 회원)

- ≤760px: 하단 탭바(주요 이동) + 헤더는 로고·알림·계정만. 보조 메뉴(설정, 고객센터, 약관, 로그아웃 등)는 햄버거.
- 탭 구성: 홈 / 공고 / QNA / 캘린더 / MY (아이콘: Home / Briefcase / MessageCircle / CalendarDays / User)
- 탭바는 1차 화면에서만 노출한다: /, /jobs, 트랙 랜딩 4종, /qna, /calendar, /mypage/dashboard.
  상세·폼·에러 화면에는 노출하지 않는다 (하단 fixed/sticky 요소와의 충돌 회피 겸 앱 문법).
- 761~1120px: 헤더 아래 컴팩트 가로 스크롤 링크 행(전체 9개 메뉴).
- 활성 탭은 검정 + font-medium. 초록 금지.
- 비로그인 MY 탭은 /login?redirect= 로 유도한다.
- 기업 회원은 기업센터 사이드바의 1040px 붕괴 패턴을 유지한다. 하단 탭바를 도입하지 않는다.

## 3. 레이아웃 규칙

- 지표(metric) 블록: 모바일에서 2열 그리드, 좌측 정렬, 장식 아이콘 없음. 3개 이상이면 가로 스크롤보다 그리드 우선.
- divide-x는 열 수가 바뀌는 브레이크포인트에서 divide-x-0으로 함께 꺼야 한다.
- 단, 행 구분선을 divide-y로 대체하지 않는다 — divide-y는 2번째 자식부터 상단선을 그어, N열 그리드의 첫 행 안쪽 셀에도 선이 생긴다. 행 구분은 [&>*:nth-child(n+{N+1})]:border-t 방식으로 "둘째 행부터"를 명시한다 (2열이면 n+3, 3열이면 n+4). 선례: CompanyDetailSections.tsx
- 고정 폭은 w-full max-w-[Npx] 관용구를 사용한다. w-[Npx] 단독 사용 금지(가로 스크롤 캐러셀 내부 제외).
- truncate/line-clamp-1은 좁은 폭에서 정보 손실이 크다. 모바일 분기에서 line-clamp-2 이상으로 완화를 검토한다.
- 그리드 아이템은 기본 min-width: auto라 콘텐츠(가로 스크롤 행 등)가 열 폭을 밀어내 문서 오버플로를 만들 수 있다. 그리드 열은 minmax(0,1fr)로 선언하거나 아이템에 min-w-0을 준다. 선례: RecruitmentCalendarClient 모바일 지원 일정 사본 (globals.css .jobs-layout의 ≤1180px 오버라이드가 1fr이라 보호 없음)
- space-y-N은 자식에 margin-top과 margin-bottom: 0을 함께 걸며 선택자 특이도가 (0,3,0)이라, 자식의 음수 마진·mb 유틸이 조용히 진다. 자식 마진과 경쟁이 생기면 space-y 대신 flex flex-col gap-N으로 전환한다 (같은 리듬, 경쟁 없음). 선례: 공고 상세 앵커 직하 여백 (9977b3b)
- 목표는 "페이지를 짧게"가 아니라 "한 화면 정보 밀도 높이기"다. 스크롤 길이 자체는 문제가 아니다.

## 4. 타이포그래피 — 위계 압축 (≤760px)

전체 축소가 아니라 위계 압축이다. 상단만 누르고 15px 이하는 절대 건드리지 않는다.
(일괄 배율 축소는 12px → 판독 불가 글씨를 만들고 위계를 무너뜨린다.)

| 데스크톱 | 모바일 | 용도 |
|---|---|---|
| 34 | 28 | 페이지 타이틀 |
| 28 | 24 | 대섹션 |
| 24 | 21 | 섹션 헤딩 |
| 22 | 20 | 서브 섹션 |
| 20 | 18 | 카드 타이틀 대 |
| 17 | 16 | 카드 타이틀 |
| 16(600) | 15(600) | 강조 본문 |
| 15 이하 | 유지 | 본문·보조·캡션·최소 |

- 데스크톱 타이포 스케일(34/28/24/22/20/17/16(600)/15/14/13/12)은 팀 확정 사항 — 이 표는 ≤760px 분기 전용이다.
- 적용은 max-[760px]:text-[Npx] 분기로 한다. 데스크톱 값을 바꾸지 않는다.

## 5. 간격 — 스텝다운 규칙 (≤760px)

배율(0.9배 등) 방식은 4px 그리드를 깬다. Tailwind 스텝을 유지한 채 한 단계 내린다.

- 섹션 간 마진: 한 단계 다운 (예: mt-16→mt-12, mt-12→mt-10, mt-10→mt-8)
- 카드 내부 패딩: 한 단계 다운, 단 p-5(20px)가 바닥 — 그 이하는 유지
- 컨테이너 좌우 여백: --shell-gutter가 담당한다. ≤760px에서 48px(좌우 24px씩) — 바닥값. 더 내리지 않는다.

## 6. 적용 시점 (타이포·간격 공통)

일괄 치환 금지. 화면을 수정할 때만 이 규칙으로 수렴한다 (브레이크포인트 수렴과 같은 원칙).
